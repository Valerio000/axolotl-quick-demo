# Contributing

Thanks for contributing! A few quick guidelines:

- Create a feature branch: `type/short-description` (e.g., `fix/load-error`, `test/add-coverage`).
- Keep PRs small and focused. Each PR should do one thing.
- Write tests for new behavior and run `pytest -q` locally.
- Use clear commit messages: `scope: short description` (e.g., `test: add extract_word_pairs edge cases`).
- Rely on the PR template for context and testing instructions.
- Be responsive to review comments and iterate on the PR.

If you plan to make major changes, open an issue first to discuss design.
